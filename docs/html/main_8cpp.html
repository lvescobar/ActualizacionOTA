Descripción detallada

Firmware del ESP32: actualizacion OTA segura, rollback por software y deteccion de anomalias con regresion logistica.

El mismo codigo genera 4 versiones (entornos de PlatformIO) que cambian con las banderas -DFW_VERSION y -DLED_MODE (ver platformio.ini).

Version Patron de LED
1.0.0 Rojo fijo
1.1.0 Amarillo parpadeando lento
1.2.0 Rojo + amarillo fijos (normal), con IA
1.3.0 Version mala a proposito (prueba de rollback)

Datos privados (clave Wi-Fi e IP del servidor): ver secrets.example.h.

bool aplicarOTA ( const String & url,

Descarga un .bin, calcula su SHA-256 mientras llega y lo instala solo si el hash coincide.

Parámetros
urlDireccion del .bin en el servidor.

Devuelve

Mientras descarga, los LEDs rojo y amarillo se alternan rapido. La particion de arranque solo cambia en Update.end(), despues de validar el hash.

◆ bootCheck()

void bootCheck ( )

Cuenta los arranques de un firmware recien actualizado.

Despues de un OTA la bandera "pending" queda en true. Si el firmware nuevo reinicia 3 veces sin llamar a marcarValida(), se marca como mala ("bad") y se vuelve a la particion anterior. Solo cubre fallos que ocurren en setup()/loop(), no en el bootloader (eso requiere CONFIG_APP_ROLLBACK_ENABLE en ESP-IDF).

void checkOTA ( )

Pregunta al servidor cual es la ultima version y la instala si es nueva.

◆ loop()

void loop ( )

Ciclo infinito: LEDs, muestreo con IA, telemetria y consulta OTA.

Gestion del dispositivo segun la IA:

  • Anomalia: muestrea cada 1 s (normal: cada 5 s).
  • Sensor caido (tacto <= 2 seis veces seguidas): estado FALLO_SENSOR.
  • RSSI < -80 dBm: envia 1 de cada 3 muestras y consulta OTA cada 60 s.
